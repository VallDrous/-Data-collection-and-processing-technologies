# Завдання:  
Варіант 37. Агент обробки електронної пошти  
Класифікація листів + автоматичні відповіді.  
Методи: NLP + classification.  

# Опис продукту:  
Створений програмний продукт є автоматизованим агентом для аналізу та класифікації електронних листів. Продукт функціонує як API, що приймає текст повідомлення, визначає його категорію як спам або не спам та автоматично підбирає сценарій відповіді. Основою для навчання моделі став датасет SMS Spam Collection, локалізований під українську мову. Текстові матеріали було перекладено, а набір ключових слів адаптовано для коректного розпізнавання спам-повідомлень. Поточна логіка дозволяє легко перейти від базового розділення на спам або не спам до розширеного багаторівневого сортування листів наприклад на "важливі", "запити", "комерційні" тощо.  

# Реалізація:  

Для реалізації даного проєкту спочатку відбувається зчитування файлу dataset_spam_email.csv, який містить дані про повідомлення та їх приналежність до спаму або не спаму. За допомогою dropna() видаляються рядки, де є NaN. Наступним кроком дані розділяються на X - вхідні та y - правильні відповіді, після чого розділяються на тренувальні та навчальні за допомогою функції train_test_split від sklearn.   
<p align="center"><img width="531" height="206" alt="image" src="https://github.com/user-attachments/assets/e82f7c73-4f53-4fd9-95eb-76390085c2c8" /></p>

Наступним етапом відбувається створення моделі завдяки Pipeline, який об'єднує кілька етапів обробки в один ланцюжок, а саме TfidfVectorizer, який виконує функцію перетворення тексту у числові вектори ознак, які модель зможе аналізувати та MultinomialNB, який виконує класифкацію на спам або не спам завдяки алгоритму наївного Байєса.      
Після створення моделі відбувається процес навчання. За допомогою функції fit відбувається навчання моделі та завдяки навчаній моделі відбувається передбачення даних, які були виділені під проведення тестування моделі. За допомогою функції accuracy_score обчислюється частка правильних відповідей та за допомогою f1_score оцінює якість класифікації з урахуванням точності та повноти передбачень.  
<p align="center"><img width="687" height="354" alt="image" src="https://github.com/user-attachments/assets/f8c9f061-6197-4080-a63e-22fcfa29b8d4" /></p>

Наступним фрагмент відповідає за автоматичні відповіді та створення API-сервісу. Створюється словник, який містить автоматичні відповіді відносно того, як було класифіковано повідомлення. Функція генерації відповіді, яка повертає значення словника відносно класифікованого класу. За допомогою FastAPI відбувається створення веб-API-застосунку.   

<p align="center"><img width="778" height="351" alt="image" src="https://github.com/user-attachments/assets/c40fd327-7bab-4d53-bc82-ba86113eb59f" /></p>

В кінці відбувається реалізація API-сервісу. За допомогою @app.get("/") створюється ендпоінт, який повертає статус роботи системи та значення метрик якості моделі (accuracy та f1_score).  
Далі за допомогою @app.post("/process") реалізується обробка вхідних повідомлень, їх класифікація на спам або не спам та формування автоматичної відповіді. Також вимірюється час обробки запиту для оцінки продуктивності системи.  
Завершальним етапом є запуск веб-сервера за допомогою Uvicorn, який забезпечує доступ до API через HTTP-запити.
